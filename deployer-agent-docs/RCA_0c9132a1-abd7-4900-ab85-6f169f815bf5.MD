## ROOT CAUSE (codice attuale DEPLOYATO — non una versione precedente)

Il codice live NON è una versione vecchia: la protezione descritta esiste ed è esattamente a `ania_importer.py:1501`, MA è agganciata al campo SBAGLIATO.

**`backend/ania_importer.py` (import rec40):**
```python
# 1497  if existing:
# 1500      # aggiorna gli IMPORTI solo se il titolo è ancora "da_incassare"...
# 1501      if existing.get("stato") == "da_incassare":
# 1502          upd = { "importo_lordo": lordo, "importo_netto": netto_calc,
#                        "imposte": ..., "provvigioni": ..., "updated_at": _now_iso() }
# 1520          await db.titoli.update_one({"id": existing["id"]}, {"$set": upd})
```

**Il flusso di COPERTURA NON cambia `stato`.** `backend/server.py:5247`:
```python
{"$set": {"titolo_coperto": True, "stato": "da_incassare", "data_copertura": data_cop, ...}}
```
La copertura setta `titolo_coperto=True` + `data_copertura` ma **lascia `stato="da_incassare"`** (il premio resta formalmente da incassare dal cliente; la copertura è un anticipo dell'agenzia).

**Collisione logica:** l'import considera `stato=='da_incassare'` come "sovrascrivibile", mentre la copertura NON sposta lo `stato` fuori da `da_incassare`. Quindi un titolo coperto-ma-non-incassato (`titolo_coperto=true`, `data_copertura` valorizzata, `stato='da_incassare'`) **passa la guardia di riga 1501 e viene sovrascritto** — nel caso specifico con `lordo=0` proveniente dal record ANIA del 09/10. La regola di business "i titoli coperti/incassati NON devono MAI essere riscritti dagli import OMNIA" NON è effettivamente applicata ai titoli *coperti* (lo è solo per quelli *incassati*, perché l'incasso porta `stato` a "incassato").

Riscontro verificato leggendo il sorgente del run attivo in sandbox (lettura statica; non riproducibile a runtime in eph perché mancano i secret/DB di produzione). La tesi "versione deployata precedente senza protezione" è **da scartare**: la guardia c'è, ma è sul campo errato.
