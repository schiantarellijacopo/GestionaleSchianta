# RCA — Google Drive "set-folder" non salva (Assicura CRM)

## Problem statement
Admin `jacopo@schiantarelli.it`, tenant attivo `c5ae2d0e-283e-4513-aaf2-cbd97ef62d78`, in PRODUZIONE: imposta la cartella root su "VISION360 - GESTIONALE" ma continua a vedere `Cartella: Assicura CRM`. Connessione mostrata come "Collegato per l'intera agenzia · dal 05/11/2026".

## Diagnosi (stato autoritativo DB produzione — `whatsapp-crm-146-test_database`, run attivo `95b5d7b0-5c1c-47b7-aa49-956969963e1e`)

### cloud_connections, provider="google_drive" — TUTTI i documenti
Esiste **UN SOLO** documento google_drive, ed è intestato al tenant **LEGACY**:

| campo | valore |
|---|---|
| tenant_id | `tenant-principale-schiantarelli` |
| agenzia_tenant_id | `tenant-principale-schiantarelli` |

| connected_at | `2026-08-10T09:57:07Z` |
| structure_initialized_at | `2026-08-10T10:10:59Z` |

### Risposte ai punti richiesti
1. **Documento google_drive con tenant_id = c5ae2d0e...? → count = 0.** Nessuna connessione intestata al tenant attivo.
2. **Documento sul tenant legacy "tenant-principale-schiantarelli"? → SÌ, count = 1.** folder_name = `Assicura CRM`, folder_id = `188eaRaNW7BfhKq_NxUxk3vSRZjsL_pF3`.
3. **cloud_folder_cache:** c5ae2d0e → **0 doc**; legacy `tenant-principale-schiantarelli` → **244 doc**. Tutta la cache è ancora sul tenant legacy.
4. **Log applicativi (ultime 24h, run attivo):** nessuna riga per `POST /api/librerie/cloud-storage/set-folder` né stack trace `cloud_storage` presente nella finestra Loki disponibile (traffico POST registrato quasi nullo: solo cron/chiamate outbound). La chiamata set-folder NON è osservabile nei log nella finestra disponibile — il 404 "Account non collegato" è un ramo HTTPException gestito che non genera traceback, quindi la sua assenza nei log è coerente ma NON prova il singolo tentativo. La root cause è provata dallo stato DB, non dai log.

## Root cause (confermata da DB)
L'endpoint `set-folder` esegue `update_one({tenant_id, provider})` con `tenant_id = c5ae2d0e...` (tenant attivo). In produzione **non esiste** alcun documento google_drive per quel tenant: l'unica connessione è ancora intestata al tenant legacy `tenant-principale-schiantarelli`. Quindi `matched_count == 0` → l'endpoint solleva `HTTPException 404 "Account non collegato"`. La UI continua perciò a leggere il documento legacy esistente (`folder_name: Assicura CRM`) e la nuova cartella "VISION360 - GESTIONALE" non viene mai persistita.

È esattamente lo **scenario "connessione ancora intestata al tenant legacy" (404 silenzioso)**, NON lo scenario "esiste già per c5ae2d0e".

## Fix
1. **Code (E1 — deploy del fix già pronto in preview):** il self-heal che adotta la connessione legacy sul tenant attivo PRIMA dell'update è corretto ed è la soluzione adeguata a questo caso. Va **deployato in produzione**. Dopo il deploy, la prima chiamata set-folder dovrà ri-intestare il documento `cloud_connections` (e idealmente la `cloud_folder_cache`, 244 doc) da `tenant-principale-schiantarelli` a `c5ae2d0e-283e-4513-aaf2-cbd97ef62d78`, poi applicare folder_id/folder_name di "VISION360 - GESTIONALE" e impostare `root_is_custom=true`.
2. **(Alternativa manuale, opzionale) Dati:** riassegnare `tenant_id`/`agenzia_tenant_id` del documento legacy al tenant attivo. Non consigliata come prima scelta rispetto al fix di codice con self-heal; richiede intervento manuale sul DB (io non modifico dati).
