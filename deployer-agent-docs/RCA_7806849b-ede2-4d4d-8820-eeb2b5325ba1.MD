# RCA — Google Drive folder structure not created for jacopo@schiantarelli.it

**App:** Assicura CRM (whatsapp-crm-146) · **Active run:** 7806849b-ede2-4d4d-8820-eeb2b5325ba1 (redeploy, success, 2026-11-05 18:45) · **DB:** whatsapp-crm-146-test_database

## Verdict
Root cause is **(A) TENANT MISMATCH** — the Google Drive connection (and all folder/data) lives under the LEGACY tenant `tenant-principale-schiantarelli`, while jacopo's active tenant is the UUID `c5ae2d0e-283e-4513-aaf2-cbd97ef62d78`. Init-structure runs against jacopo's active tenant, finds no connection there, and aborts — creating nothing.

Ruled OUT: **(C) stale image** and **(B/stale cache)** — see evidence below.

## Why nothing is created (code trace)
Every cloud-storage endpoint resolves tenant via `_tenant_id(user) = user.agenzia_tenant_id` → for jacopo that is `c5ae2d0e...`.
- `POST /api/cloud-storage/init-structure` → `_init_structure_for_tenant("google_drive", "c5ae2d0e...")`.
- First statement: `conn = await db.cloud_connections.find_one({"tenant_id": "c5ae2d0e...", "provider": "google_drive"})` → **None** (connection only exists under the legacy tenant).
- `if not conn: raise HTTPException(409, "Account non collegato per questo provider")`.
=> The call returns 409 and never reaches folder creation. The frontend does not surface this 409, so the user sees "nothing happened / no error."

Note: the stale-cache theory cannot apply here — `cloud_folder_cache` has **48 docs, ALL under `tenant-principale-schiantarelli`** (dated Aug 2026, old layout with no "Archivio" prefix) and **0 under `c5ae2d0e...`**; and the new code clears cache at init start regardless.

The "UI shows connected" impression comes from the connection/data having been established under the legacy account (admin@assicura.it / tenant-principale-schiantarelli). Under jacopo's active tenant `/status` returns an empty connection list. This is exactly the legacy→per-agency split the app's own `POST /api/cloud-storage/migrate-tenant` endpoint exists to resolve (it rewrites `tenant_id`/`agenzia_tenant_id` from the legacy principale tenant to the user's active tenant across cloud collections).

## Fix
1. **Move the connection + data to jacopo's active tenant** (preferred, preserves existing Drive links): run the in-app migration `POST /api/cloud-storage/migrate-tenant` with `source_tenant_id = tenant-principale-schiantarelli` (blank also defaults to the legacy principale) while logged in as jacopo@schiantarelli.it — it reassigns `cloud_connections` (+ folder cache, documents, inbox) from the legacy tenant to `c5ae2d0e...`. Then press "Riorganizza (INBOX + ARCHIVIO)". OR simply **re-connect Google Drive while logged in as jacopo@schiantarelli.it** — the OAuth callback upserts the connection under `c5ae2d0e...` and auto-runs init-structure (this creates a fresh "Assicura CRM" tree under the active tenant; legacy data stays orphaned).
   - Equivalent DB data fix if done manually: set the single `cloud_connections` doc's `tenant_id` and `agenzia_tenant_id` to `c5ae2d0e-283e-4513-aaf2-cbd97ef62d78` (and migrate the 48 `cloud_folder_cache` docs or let init regenerate them).
2. **(Optional, Code/E1 — UX gap)** The frontend should surface the `409 "Account non collegato per questo provider"` from init-structure instead of failing silently; the silent swallow is what made this look like "connected but does nothing."
