## ROOT CAUSE

**Symptom #2 ("Scansiona INBOX ora" reads 0 PDFs) — CONFIRMED:**
jacopo operates as tenant `c5ae2d0e…`, which has **no `cloud_connections` doc, no `cloud_folder_cache` INBOX pointer, and no `cloud_scan_history`**. The whole Drive/OCR setup lives only under the legacy `tenant-principale-schiantarelli`. A scan under the current tenant has no Drive connection to open → 0 files read, nothing written. (The `_scan_all_tenants_job` scheduler scans the legacy tenant, which long ago reached in_attesa 0, so it also produces nothing new.)

**Symptom #1 (auto-archive does nothing on the 13 pending) — PARTLY data, PARTLY code/config:**
- 3 of 13 (carta_identita) legitimately cannot auto-match — codice_fiscale is null (2) or has no matching anagrafica (1).
- 10 of 13 (libretto) DO have matches available: 7 have an existing matched anagrafica, and 9/10 targhe have at least one (often active) policy in `polizze` for this tenant — yet `target_polizza` is null on all and they stay pending. That is not a "no data" case; it indicates the archive/matching code does not link a polizza-by-targa (candidate causes: never attempts targa→polizza link; bails on ambiguous multiple-active-policy targhe; or cannot complete archival because there is no Drive connection for this tenant to move the file into). **This needs E1 to read the auto-archivio / cloud_ocr_scanner matching code.** Not reproducible from DB/logs alone; no app secrets/Drive access in the sandbox.
